Page header typography: how the data flows

Read top to bottom. Colored boxes are files, arrows are what is passed, the red box is what comes out. Sass runs at build time; the browser only sees the last step.

values (level map) theme group (roles) function result (CSS) not built yet
1
themes/fdpg-light/_type-roles.scss Defines the values. One entry per role, same name as in the group file. Only place with numbers. 
$fdpg-light-type-roles: (
  'app-content-page-header-title': (family: 'Titillium Web', weight: 600, size: 24px, line: 32px),
  'app-content-page-header-intro': (family: 'Titillium Web', weight: 400, size: 16px, line: 24px),
);
passes the whole map $fdpg-light-type-roles (via @import )
2
themes/fdpg-light/_theme.scss Puts the map into the one $theme that every mixin receives. 
$num-portal-webapp-theme-fdpg: map.merge( ..., ( type-roles: $fdpg-light-type-roles, roles: ..., foreground: ... ) );
passes $theme as the argument of the mixin page-header_themed($theme)
3
custom-material/typography/_page-header.themed.scss Roles only. Says which level each part of the page header uses. No numbers. 
@mixin page-header_themed($theme) {
  @include type.vars($theme, 'app-content-page-header-title');
  @include type.vars($theme, 'app-content-page-header-intro');
}
calls type.vars($theme, 'app-content-page-header-title')  ·  arguments: the theme and the role name (the key in step 1 and the variable prefix: one name everywhere)
4
functions/_type.scss Looks the level up and writes four variables. Not the CSS shorthand font: , because that resets every font property it does not name. 
@mixin vars($theme, $name) {
  $l: map.get($theme, type-roles, $name);
  --font-#{$name}-family: #{map.get($l, family)};   /* ... also -weight, -size, -line */
}
lookup in $theme[type-roles]['app-content-page-header-title']
writes (4 declarations) --font-app-content-page-header-title-family / -weight / -size / -line
writes the declarations into the mixin of step 3, so they end up inside .FDPGTheme
5
compiled CSS (what the browser gets) Four variables per role. Built once, shared by all components. 
.FDPGTheme {
  --font-app-content-page-header-title-family: 'Titillium Web', sans-serif;
  --font-app-content-page-header-title-weight: 600;
  --font-app-content-page-header-title-size: 24px;
  --font-app-content-page-header-title-line: 32px;
  --font-app-content-page-header-intro-family: 'Titillium Web', sans-serif;
  --font-app-content-page-header-intro-weight: 400;
  --font-app-content-page-header-intro-size: 16px;
  --font-app-content-page-header-intro-line: 24px;
  --app-content-page-header-intro-measure: 70ch;
  --font-app-content-page-header-actions-size: 16px;
}
read by the component SCSS with var(...)  ·  step 4 of the process, to be discussed
6
shared/components/header/header.component.scss (not changed yet) Four plain lines, same properties as today, but the values come from the theme. Nothing else is touched. 
.header-font {
  font-family: var(--font-app-content-page-header-title-family);
  font-weight: var(--font-app-content-page-header-title-weight);
  font-size: var(--font-app-content-page-header-title-size);
  line-height: var(--font-app-content-page-header-title-line);
}

Change one value

Title should be 28px: edit one number in step 1 ( size: 28px ). Steps 2 to 5 are untouched, and every component that reads --font-app-content-page-header-title-size follows.
