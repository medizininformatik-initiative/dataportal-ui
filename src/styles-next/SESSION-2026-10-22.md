Nothing from this session is committed. Nothing was checked in a browser by Claude; Shah looked at the action bar buttons only. All SCSS compiles (`npx sass --load-path=. --load-path=node_modules src/styles-next/styles.scss`). Only `src/styles-next/` and a few component SCSS files changed, never `src/styles/`.

## 1. Insights

**Buttons and layout**
- The app had no button hierarchy. Most action bar buttons were `type="green"` filled, so "Send query" and "Back to search" looked the same. The research and plan files never defined primary or secondary buttons, only color variants (`blue`, `green`, `red`, `cancel`).
- Decision of the session: **the place decides the color, not a primary/secondary fill.** Inside `num-action-bar` every button is green. Everywhere else (boxes, filter bar, modals, header) the button is the existing `blue` variant. `red` stays for delete. This needs no new button look.
- The action bar tint was a `::before` overlay (absolute, `opacity: 0.1`). It paints above non-positioned children, so it tinted every button and white could never show. Fix: the tint is now a gradient on the container background (`linear-gradient(rgba(green, 0.1), same), white`). No overlay, nothing to lift.
- `opacity` on a button lets the background through, so a faded disabled button blends into the bar. Disabled is now a white button with a green icon and the existing green ring.
- Enabled and disabled looked the same when both were white with a green ring. The agreed look: enabled = green fill, white icon; disabled = white fill, green icon.
- Keyboard focus fills the button with a darker color, so an icon color that matches the fill hides the icon. Always set the icon color for the focus state too.

**Contrast**
- Green 500 `#9bb823` is 2.26:1 against white, in both directions. Every green button, badge and outline fails WCAG AA. Green 800 `#607311` is 5.31:1.
- Icon contrast comes only from the fill behind the icon. A ring, halo or fade changes the button edge, not the icon. In the prototypes only the darker-fill versions improved the icon.
- WCAG asks 3:1 for a UI edge. The 7:1 "AAA" figure is a text level. Blue 700 is 7.24:1, green 900 is 8.16:1, so both pass either way.
- Grey meta text `#6a7483` falls below 4.5:1 on the new tints: 4.30 on 50, 3.99 on 75, 3.67 on 100. This is a conflict between our new fills and the old text color.
- Accent 500 text on a 100 fill is 4.35:1 and 600 on a 200 fill is 4.28:1. So text on 200 needs 700 (5.52).

**Blue ramp and tints**
- The ramp has one hue (217 to 220 degrees); saturation rises from 30% to 45% with darkness. No hue change is needed.
- Alpha tints (`rgba(accent, 0.1)`) change with whatever is behind them. The 10% tint of the new 500 is about shade 50, the 20% tint about shade 100. Opaque shades are predictable.
- `.num-card` (data selection box) still used an alpha overlay (`::before`, 10%). It is now a solid 50 fill.
- Three components used accent 400 as text or icon color with a dark fallback (`#345396`). 400 is too light for text, so they moved to 600.
- A full-step hover (50 to 100) is too strong on a large box. A half step (new shade 75) works for boxes; a full step is fine for small items and for a 1px border.
- The research file covers typography; color appears only in its section 6 (contrast table) and section 8 (ideas). It did not measure hover, focus or disabled states. Section 8 already proposed `#49689c` for the reset button, links and toggle, which is the new accent 500.
